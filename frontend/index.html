Two production ML models · Real procurement data

Read every invoice like an auditor would.

Invoice Intelligence System is a full-stack ML application trained on 5,543 real vendor invoices. One model predicts freight cost before a shipment ships; the other flags invoices that need a human's eyes before they get paid. Both are live below — not mockups.

Pipeline

From raw procurement data to a live prediction

Both models are trained offline from the same SQLite database, then served by a FastAPI layer that loads the trained artifacts once and keeps them in memory.

01

Ingest

A real SQLite database of vendor purchases, invoices, and pricing — 5 tables, 2.37M+ purchase line items.

vendor_invoice · purchases

02

Engineer

SQL joins aggregate purchase-order totals and timing into the exact feature set each model trains on.

data_preprocessing.py

03

Train & Select

Three candidate algorithms compete per task — the best one on held-out test data is what actually ships.

train.py → models/*.pkl

04

Serve

FastAPI loads both trained models once at startup and exposes them as a REST API this page calls directly.

backend/main.py

How good are these models, really?

Real, reproducible test-set metrics — not cherry-picked numbers. Both models were evaluated on the same 80/20 held-out split (random_state=42) of the 5,543-invoice dataset.

Freight cost scales almost linearly with invoice value in this dataset, so the simplest model wins — lowest MAE on the test set is the selection rule in train.py, not a fixed preference for linear models.

API reference

Built to be called, not just clicked

Every prediction on this page goes through a documented REST API you can call directly from your own code.
